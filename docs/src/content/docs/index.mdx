`oss` is one command that answers from **what is already on your machine** — the
repositories you follow, the notes you keep, the files in front of you — and
only reaches for a model when it needs one.

**A GitHub token is the whole requirement.** Every download carries its own Java.
A local model, a cloud key and a notes folder each make it sharper, and none of
them is needed to start.

## Two minutes to a first answer

```bash
brew install ramanathan1504/oss-cli/oss
export GITHUB_TOKEN=$(gh auth token)

oss sync --add owner/name    # register a project you follow
oss sync --all               # pull it down; builds the index as it goes

oss search "connection pool exhausted"   # have I seen this before
oss ask "why does the retry loop give up after three attempts?"
```

`owner/name` is a placeholder. Put your own repository there — a project you
maintain, one you contribute to, or one you are trying to understand.

## `ask` is the front door

Everything else on this site is a specialised version of one question. `ask`
reads your corpus, opens the files it needs, runs the project's own build when
you allow it, and proposes edits as diffs you approve one at a time.

```bash
oss ask                              # keep asking; ctrl-d leaves
oss ask "what changed in the rollover path this month?"
oss ask --issue 4129 -r owner/name   # about one issue, with what is already known
oss ask --allow-run "do the tests pass?"
oss ask --allow-edit "fix the null check in the parser"
```

It answers from your own archive **before** it asks anything else — see
[Skills](/docs/skills/) for the instructions it works from, and
[Where an answer comes from](/docs/conversations/) for how it chooses a model.

## What is actually there

| | |
|---|---|
| **44 commands** | `oss --help` shows the 20 worth knowing; `oss --help-all` lists the other 24 |
| **One that needs nothing** | after the first sync, your archive answers with the network unplugged |
| **Six that go and get something** | `sync` `issue` `pr` `hub` `followup`, and `doctor` when it checks what is reachable |
| **One that sends** | `bug` files a fault in oss itself — after printing the whole issue and asking |
| **Five that name who answers** | `llm` `claude` `gemini` `codex` `junie` — a prefix in front of any command |
